# LEARNINGS — ハーネス自己改善ログ

`/retro` が蓄積する「このプロジェクトで分かったこと」の記録。
新しい罠を踏んだ・手順が実態とズレた・縛りすぎていた、と気づくたびにここへ1エントリ追記する。
ここに溜まった学びは、次の `/retro` で CLAUDE.md やコマンドへ昇格（反映）される候補になる。

## 書き方（1エントリ）

```
## YYYY-MM-DD — <短いタイトル>
- **状況**: 何をしていたときに気づいたか
- **学び**: 何が分かったか（罠 / 改善 / 過剰制約の発見）
- **反映先**: CLAUDE.md §N / commands/<name>.md / なし（記録のみ）
- **種別**: invariant | gotcha | command-fix | fact | loosen
```

- 既存エントリと重複する学びは、新規追記せず該当エントリを更新する
- 反映先に書き込んだら、そのエントリに `→ 反映済み` を追記してよい

---

## 2026-06-09 — 自己改善ループを導入
- **状況**: トレンドリポジトリ調査をもとにハーネス設計を見直す中で、CLAUDE.md・10コマンドがすべて静的（一度作って固定）で、運用しながら手順を直す経路が無いことが判明した。
- **学び**: ハーネスは「手順を細かく縛る」より「不変条件＋自己修正ループ」で運用する方が、実態とのズレに強い。手順を固定すると現実が変わったときに壊れる。
- **反映先**: CLAUDE.md §10（自己改善ループ）/ commands/retro.md（新規）
- **種別**: loosen / command-fix
- → 反映済み

# 振り返り — ハーネス自己改善ループ（/retro）

直近の作業を振り返り、**ハーネス（CLAUDE.md・各コマンド）自身が実態に合っていたか**を点検し、
ズレ・罠・改善点を最小 diff で反映する。これがこのプロジェクトの「都度手順を見直して更新する」仕組みの中核。

> 目的は**手順を増やして縛ること**ではなく、**次回より確実に正しく動くための最小の前提だけ**を残すこと。
> 学びが無ければ何も足さない（ハーネスの肥大化を避ける）。

## 引数

`$ARGUMENTS` — 省略可。

- **空**: 直近の作業範囲を自動特定して振り返る
- **フォーカス語（例: `deploy` / `mobile`）**: その手順／コマンドに絞って振り返る
- **`--dry`**: 反映はせず、提案（差分案）だけを提示する

## 手順

### 1. 振り返る範囲を特定
- `git log --oneline -10` と `git diff --stat HEAD~N` で、今セッションで何を変えたかを掴む
- `.claude/LEARNINGS.md` を読み、既出の学びを把握（重複追記を防ぐ）

### 2. 3つの問いで振り返る
今回の作業について、具体例とともに洗い出す:
- **Keep（効いた）**: ハーネスのどの手順・原則が実際に役立ったか
- **Friction（摩擦）**: 手順が実態と違った／足りなかった／**過剰に縛っていた**箇所はどこか
- **Drift（陳腐化）**: CLAUDE.md の事実（行数・店舗数・init 関数一覧 等）やコマンド手順が、現状とズレていないか

### 3. 各学びを分類する
洗い出した項目を、反映先で仕分ける:

| 種別 | 判定 | 反映先 |
|------|------|--------|
| **不変条件 (invariant)** | 破ると壊れる・必ず守るべき | CLAUDE.md §2 か該当コマンドに1行追記 |
| **罠 (gotcha)** | 知っていれば避けられた落とし穴 | `.claude/LEARNINGS.md` に追記 |
| **コマンド修正 (command-fix)** | 手順が実態と乖離していた | 該当 `commands/*.md` を Edit |
| **事実更新 (fact)** | 行数・店舗数・トークン等の事実が変わった | CLAUDE.md の該当行を Edit |
| **過剰制約の緩和 (loosen)** | 縛りすぎで動きを妨げていた | 該当箇所を「既定値(soft)」に格下げ or 削除 |

判断に迷う学びは追記せず、§5 の報告で「保留」として挙げるだけにする（憶測でハーネスを変えない・No Guessing）。

### 4. 反映する（`--dry` 指定時は提案のみ）
- 反映は**最小 diff**で。既存項目と重複する学びは新規追記せず、既存の記述を更新する
- `.claude/LEARNINGS.md` に1エントリ追記（フォーマットはファイル冒頭の定義に従う）
- **サイト本体（`*.html` / `css/` / `js/` / `img/`）は変更しない。** 触ってよいのは `.claude/` 配下と `CLAUDE.md` のみ
- 新しい制約を足すときは「不変条件」か「既定値(soft)」かを明示する。soft は破ってよい前提で書く

### 5. 報告
- 反映した更新の一覧（ファイル ↦ 何を変えたか）
- `LEARNINGS.md` の新規エントリ
- 「次回からこう変わる」を1〜3行で
- 反映を保留した学び（あれば）と、その理由

## 注意事項
- **足し算より引き算**: 古くなった手順・効かなかった制約は、見つけたら削るか soft に格下げする
- **1回1テーマ**: 大量の学びを一度に詰め込まない。重要な2〜3件に絞る
- **コミットは任意**: 反映後のコミットは `/deploy` か通常の git 操作で。`/retro` 自体は commit しない
- このコマンド自体も振り返り対象。`/retro` の手順が回しにくければ、この `retro.md` も更新してよい
